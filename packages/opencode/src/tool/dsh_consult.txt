- Consult DeepSeek Harness (dsh) as an external coding advisor via the local `dsh` CLI
- Spawns a one-shot agent: `dsh --profile <profile> [--patch <file>...] "<prompt>"` (profile defaults to headless)
- Returns the final assistant text on stdout (no streaming JSON transcript)
- Supports user intervention in the external consultation child session (follow-ups re-run with prior transcript context, same profile and patches)
- Use when you want an independent DeepSeek Harness judgment without making it the primary executor

When to use:
  - Architecture review, alternative approach, risk analysis
  - Second opinion on a plan, bug diagnosis, or design trade-off
  - Implementation-oriented advice from a full DeepSeek coding agent

When NOT to use:
  - Simple file reads/searches you can do with read/grep/glob
  - When the user did not ask for external consultation and local tools suffice

Usage notes:
  - Provide a self-contained prompt: goal, relevant absolute paths, constraints, and desired output format
  - dsh starts cold — it cannot see this conversation unless you put the context in `prompt`
  - Defaults to the current project directory; optional `working_directory` overrides cwd
  - `profile` selects the dsh plugin composition to boot (default "headless"); a custom profile changes which model adapters, tools, presets, and bundles mount
  - `patch` accepts inline `cordis.patch.yml` YAML content (or a list) applied via `dsh --patch` after the profile layer, to override model/tools/persona/presets per consult without touching ~/.dsh
  - Requires `dsh` on PATH (`npm i -g @deepseek-ai/dsh`) and `DEEPSEEK_API_KEY` (or credentials under ~/.dsh)
  - dsh is a full coding agent; prefer analysis-scoped prompts unless the user wants implementation
  - Desktop intervention keeps the tool call open after the first answer; follow-ups are new runs with replayed history

Result handoff:
  - Successful calls include a versioned `external_consultation` block with the OpenCode child `task_id`, summary previews, and intervention flags.
  - If `read_before_summary` is true, call `task_transcript` with `read_transcript.arguments` BEFORE summarizing. Follow next_cursor to inspect earlier relevant answers, not just the last intervention reply.
  - Summary fields are previews. The complete conversation is persisted in the child session; use task_list to rediscover it if needed.
  - Reading a transcript does not rerun DSH. Do not use task to resume this external session or repeat the consultation to recover history.
  - If `delivery` is `inline_fallback`, transcript reading is unavailable for this turn and the full text history is supplied inline instead.
