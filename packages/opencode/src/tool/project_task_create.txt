Create a NEW durable project-level task for the current project.

Project tasks outlive a single session and can be mounted onto one or more sessions.
Session-local step checklists belong in `todowrite`, not in project-task titles.

Description is stored as a user-visible file at `.opentasks/<taskID>/description.md`
(DB keeps only the relative path). Agents may put other task-related files under
`.opentasks/<taskID>/`.

## When to use
- User wants a new project-scoped work item (goals, acceptance criteria, multi-session work)
- You already ran `project_task_list` (or know no open/in_progress task covers this work)
- Creating a child-like workstream that is intentionally separate from existing tasks

## When NOT to use
- Session is already mounted to the correct task → use `project_task_update` / `todowrite`
- Work is only a per-session checklist (3+ coding steps) → use `todowrite`
- Marking progress/done, retitling, or editing description → use `project_task_update` with the existing taskID
- An open/in_progress task with the same title or same goal already exists → `list`/`get`, then `mount` or `update` — NEVER create a duplicate
- Finishing work → NEVER create another task with status done; update the existing task

## Rules
- Default status is `open`. Allowed on create: `open` or `in_progress` only
- Do NOT create with status `done` or `archived` to "finish" work
- After create, if the user is working on it now, `project_task_mount` this session onto the new taskID
- Prefer short, stable titles; put goals/acceptance criteria in `description`

## Flow
1. `project_task_list` — avoid duplicates
2. `project_task_create` — only if truly new
3. `project_task_mount` — attach current session when relevant
4. `todowrite` — session step checklist
