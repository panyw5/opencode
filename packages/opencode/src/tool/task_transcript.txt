# PURPOSE
Inspect the persisted transcript of a child task or external CLI consultation (Codex, Claude, Grok, or DSH).

Use this when a subagent is stuck, failed, produced an unexpected result, or needs more direction. Inspect its recent messages and tool activity before deciding whether to resume the task.

## EXTERNAL CONSULTATION HANDOFF
- CLI consultation results include an `external_consultation` protocol block with `version`, `task_id`, `summary`, `user_intervened`, `user_turns`, `read_before_summary`, and a `read_transcript` tool call.
- `task_id` is the OpenCode child session ID, NOT the CLI's `thread_id` or native `session_id`.
- When `read_before_summary` is true, call this tool using `read_transcript.arguments` BEFORE summarizing the result. The initial request and important earlier answers may differ from the final intervention message. Summary fields are short previews, not full answers.
- Start with `include: ["text"]`. Follow `next_cursor` backwards until you have inspected the original request and relevant earlier answers. Read tool activity only when needed to inspect searches, commands, failures, or sources.
- Do not conclude that an external advisor failed the original request merely because the last user intervention was unrelated small talk.
- Reading does not restart the advisor. An external consultation's `task_id` is a read reference; do NOT pass it to `task` to resume the CLI. Do not repeat a consultation to recover history.

# GUIDELINES
## PARAMETERS
- `task_id` — REQUIRED, string. Child session ID from `task`, `task_list`, or the `external_consultation` handoff.
- `cursor` — optional, string. The `next_cursor` value returned by a previous call. Omit it on the first call.
- `limit` — optional, integer. Messages to return per page. Default 20, maximum 50. Prefer the default or a small page; do NOT read the whole transcript unless it is necessary.
- `include` — optional, array of these values: `text`, `tool`, `reasoning`. Which content to return. Default is `text` + `tool`. `reasoning` is excluded unless you list it explicitly.

## PAGINATION
The first call (no `cursor`) returns the most RECENT page. Each response reports `more` and, when older messages exist, `next_cursor`. To read backwards through history, pass the previous response's `next_cursor` as `cursor`; repeat until `more` is `false`.

## RESPONSE
- Header: `task_id`, `title`, `messages` (entries in this page), `more`, and `next_cursor` when present.
- Each entry starts with `[role] message_id: ... created: ...`. An assistant entry may add `finish: ...` or `error: ...`.
- Message content appears as `text:` blocks; reasoning as `reasoning:` blocks (only when requested).
- Tool entries appear as `tool: <name> (<status>)` followed by `input: <value>`, plus `output:` when the status is completed, `error:` when it failed, or `title:` while it is still running.
- Each field is clipped to 4000 characters. Paging retrieves older messages, not the truncated tail of a field. Do not claim to have inspected content that was truncated.
