# PURPOSE
Launch a new agent to handle complex, multistep, long-horizon tasks autonomously.

When using the Task tool, you must specify a subagent_type parameter to select which agent type to use.

When NOT to use the Task tool:
- If your task is SIMPLE and can be completed by calling the provided TOOLS, like `Read`, `Glob`, `Websearch`
- If no available agent is a good fit for the task, do it yourself

# GUIDELINES
- Launch multiple agents concurrently whenever possible, to maximize performance; to do that, use a single message with multiple tool uses
- When the agent is done, it will return a single message back to you, invisible to the user. Summarize the result by sending a concise message to the user.
- Each agent invocation starts with a fresh context.
  - Your initial prompt should contain a highly detailed and focused task description for the agent to perform autonomously.
  - Specify exactly what information the agent should return in its final message to you.
  - State clearly whether it should write code or research (search, file reads, web fetches, etc.) ONLY.
  - Tell it how to verify its work if possible.
- The output includes a `task_id` for resuming the same subagent session with `task(task_id=...)`. Use `task_transcript` to inspect subagent activity before resuming.
- If a task call is interrupted before returning its `task_id`, use `task_list` to rediscover child task sessions.
